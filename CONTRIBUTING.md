# Contributing

Help keep this catalog accurate, sourced, and useful.

## Model-entry requirements

1. Link the exact checkpoint, model card, official family page, or hosted endpoint. A base-family link alone does not prove a derivative's provenance.
2. Record exact version, access method, provider/route for hosted models, and the date checked.
3. Identify the base model and modification type when known: fine-tune, LoRA, refusal-direction ablation, prompt wrapper, or other.
4. State the license and any base-model, provider, or redistribution terms. Use “unknown” rather than guessing.
5. Separate model behavior from interface filters, provider policy, and post-processing.
6. Back low-refusal claims with a reproducible test description. Label unverified entries community-reported or to verify.
7. Do not include personal data, private datasets, or real-person sexual examples.

## Pull request checklist

- [ ] Source and exact version are provided.
- [ ] Access method and availability are current.
- [ ] Provenance and license are clear or explicitly marked unknown.
- [ ] The “uncensored” characterization is appropriately qualified.
- [ ] No service or provider name is used as a substitute for model provenance.
- [ ] The entry adds distinct value and is not a duplicate variant without a reason.
